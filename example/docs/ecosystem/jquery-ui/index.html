jQuery UI coexistence and migration

Keep existing jQuery UI regions application-owned while you migrate one feature at a time to semantic HTML and native jQStar components. New work should use jQStar directly.

No compatibility facade: a similar component name does not promise Widget Factory, plugin, method, option, event, data, Position, effect, theme, or third-party extension compatibility.

Verified boundary

The fixture pins jQuery 4.0.0 and jQuery UI 1.14.2 with the official base theme. It runs beside packaged jQStar output in Chromium, Firefox, and WebKit, plus touch, reduced-motion, forced-color, and JavaScript-disabled modes. jQuery UI is a development fixture only; it is absent from jQStar runtime dependencies, package paths, installed consumer trees, and entry graphs.

The full inventory maps 72 unique official API pages exactly once. It covers all 15 widgets, 6 interactions, 34 effect entries, methods, selectors, utilities, Widget Factory contracts, and theming. Third-party widgets remain application-specific.

No equivalent jQStar does not publish the legacy API or behavior.

Keep ownership separate

  • A legacy island owns its UI instances, generated wrappers, data, events, theme, portals, and explicit destroy.
  • A jQStar island owns its data-jqs root, data-part slots, state, named actions, focus, and disposal.
  • Destroy the current owner before a server response replaces its island, then initialize only the incoming owner.
  • Do not patch $.widget, read private UI data, auto-initialize legacy markup, or run both systems on one element.

Migrate the project editor

  1. Record the exact legacy behavior, form values, server requests, focus, keyboard, touch, responsive, and no-script baseline.
  2. Add jQStar beside the untouched legacy island and verify package, data, event, CSS, overlay, and focus isolation.
  3. Move date input, autocomplete, tabs, sortable order, and dialog one semantic region at a time.
  4. Preserve native names, values, validation, submitters, server behavior, direct URLs, and keyboard alternatives.
  5. Release and observe the region, then explicitly destroy and remove its old UI code and theme assets.

Adapter decision

No adapter ships. The project-editor and command-toolbar slices need different facades. The measured sketches save only 13 lines (7.9%) and 7 lines (7.7%), below the frozen 25% and 20-line thresholds. A shared surface would also exceed the two-widget limit and has no executable accessibility, gzip, type, coverage, or browser proof.

Direct semantic migration removes the legacy lifecycle and runtime cost. A future adapter needs new observed demand and a separate bounded ticket.

Accessibility and rollback

The exact fixture retains four serious or critical legacy axe rules across seven nodes and adds none in native or partially migrated islands. It also verifies touch targets, reduced motion, forced colors, native validation and submission without JavaScript, explicit destroy before server replacement, sibling identity, and independent documents.

Release one island behind an application-owned switch. Keep the prior template and assets deployable until checks pass. Rollback disposes the current owner, restores only that island, and initializes the previous owner.
