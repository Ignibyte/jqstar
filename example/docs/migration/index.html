Migrate to 1.0

The 1.0 root entry preserves the 0.1 compatibility baseline. The main upgrade is choosing whether to keep that complete root or adopt stable, explicit package entries.

Keep the compatibility root

main.ts 
import $ from "jquery";
import "jquery-star";

$("#app").star();

This still auto-installs core, Datastar, and UI behavior. It still uses trusted JavaScript expressions and the core.datastar request profile by default. Existing data-signals, directives, actions, request events, and UI methods retain their recorded meanings.

Choose explicit entries when needed

main.ts 
import $ from "jquery";
import { installStarCore } from "jquery-star/core";
import { datastarPlugin } from "jquery-star/datastar";
import { uiPlugin } from "jquery-star/ui";

const installed = installStarCore($);
installed.star.use([datastarPlugin, uiPlugin]);
installed.star.boot(document);

Modular imports are inert until explicitly installed. Import jquery-star/testing only in tests. Use jquery-star/datastar/testing for deterministic Datastar fixtures.

Review lifecycle and extension changes

  • Register plugins before the first application starts; installation is transactional.
  • Use $.star.whenEnhanced() before inspecting a server-patched DOM.
  • Use $.star.dispose() for terminal document shutdown and inspect its report.
  • Move reusable behavior into namespaced public plugins, directives, helpers, or actions.
  • Use the testing harness with a caller-owned same-realm document and jQuery instance.

CSP, Turbo, and htmx are opt-in

The root does not silently switch expression languages. Install jquery-star/csp before other plugins to use the finite grammar; move ambient globals, arbitrary calls, and unapproved jQuery methods into registered application actions or helpers. Do not import the compatibility root into the same jQuery owner.

Turbo and htmx continue to own requests, history, focus, and DOM mutation. Their explicit bridges add jQStar cleanup, preservation, and re-enhancement around supported host events. See the bridge contract.

jQuery UI and Mobile applications

jQStar does not bundle either archived runtime and does not claim to be an official successor. Isolate and destroy application-owned jQuery UI regions while migrating them to native components. Migrate jQuery Mobile route by route to server documents, semantic HTML, responsive CSS, native forms, jQuery 4, and bounded jQStar enhancement.

Continue with the detailed jQuery UI guide or jQuery Mobile guide.

Names that do not change

Use jQStar for the product, jquery-star for npm imports, jqstar for the CLI and repository, and data-jqs for component roots. The plugin API remains 0.1.0; the CSP grammar remains jqstar-csp-expression/1.
