Security

Report suspected vulnerabilities privately. Do not include secrets, private customer data, or exploit details in a public issue.

Use the repository's private vulnerability report form. Include the affected version and entry, impact, reproduction, and any proposed fix.

Response and supported versions

Maintainers aim to acknowledge a complete report within three business days and provide an initial triage within seven. The current 1.x minor is maintained; the previous 1.x minor receives security fixes for six months after the next minor ships.

Application responsibilities

  • Authenticate and authorize every server operation.
  • Apply CSRF defenses and validate all request data on the server.
  • Encode text and sanitize any application-trusted HTML before rendering it.
  • Protect secrets, response data, logs, and deployment configuration.
  • Configure CSP, Trusted Types, allowed origins, and third-party scripts for the site.

jQStar coordinates browser behavior; it is not an authorization layer, HTML sanitizer, secrets store, or network policy.

Expression engines

The compatibility root evaluates application-authored JavaScript and therefore needs a CSP policy that permits dynamic evaluation. The explicit jquery-star/csp entry uses a closed finite grammar without dynamic code construction. It still requires trusted markup and trusted installed extensions and is not a sandbox for attacker-authored expressions.

Read the complete CSP expression contract before selecting the finite runtime.

Release response

A vulnerable release may be deprecated in npm and its GitHub release returned to draft while a fixed version and advisory are prepared. Package evidence includes dependency advisories, lock integrity, licenses, exports, lifecycle scripts, generated artifacts, and the exact packed bytes.
