Datastar Integration

Keep local behavior beside server-rendered HTML. The server can patch signals and regions with JSON, HTML, or Datastar SSE.

One protocol boundary: jQStar consumes Datastar-compatible events. Your server must generate SSE with @starfederation/datastar-sdk, never handwritten event strings.

Call the backend from HTML

The root defaults to core.datastar. Core alone uses core.generic with explicit inputs and JSON/HTML. Select the generic profile for ordinary endpoints.

application.html 
<button data-on:click="@get('/items')">Refresh</button>

<form method="post" action="/items"
  data-on:submit__prevent="@post('/items', { contentType: 'form' })">
  <input name="title" required />
  <button>Save</button>
</form>

Datastar GET sends filtered signals in the datastar query; JSON DELETE uses both query and body. Datastar requests include Datastar-Request: true. Form mode uses native form encoding. For submission without JavaScript, the endpoint must return useful HTML or a redirect.

Response behavior

Response jQStar result
application/json Deep-patch signals; a null value removes a signal.
text/html Morph elements by ID or the Datastar selector and mode headers.
text/event-stream Apply Datastar signal and element patches as they arrive.
204 No Content Complete the request without changing the application.

Generate streams with the official SDK

Terminal 
npm install @starfederation/datastar-sdk
server.ts 
import { ServerSentEventGenerator } from "@starfederation/datastar-sdk/node";

const read = await ServerSentEventGenerator.readSignals(request);
if (!read.success) {
  response.writeHead(400).end(read.error);
  return;
}

await ServerSentEventGenerator.stream(request, response, (stream) => {
  stream.patchSignals(JSON.stringify({
    count: Number(read.signals.count ?? 0) + 1,
  }));

  stream.patchElements('<li data-text="$count"></li>', {
    selector: "#feed",
    mode: "append",
  });
});

One read for several regions

Put a named backend action in a registry block when several regions need the same record. An outer data-jqs coordinator can contain independently owned consumer roots. Share the selected ID through an optional store and return one SDK response that patches their stable content targets. Patches stay inside the initiating application's boundary.

The block owns cancellation and subscriptions. Retain a request while another consumer still needs it, and release it when the last consumer leaves or the kernel is disposed. Keep initial HTML, native links and form actions useful without JavaScript. After a write, refresh canonical output; validation, permissions and versions stay on the server.

jQStar does not ship a resource cache or mutation package. HTTP caching can reduce origin work, but correctness must hold when a browser requests the record again. Applications needing a shared JSON cache can evaluate an external core in an application-owned plugin with explicit lifecycle cleanup.

Enhancement after a patch

New directives and components are enhanced without another .star() call. Morphs retain matching nodes and their handlers, restore focus, and protect the active input's value. Other values can receive server updates; removed nodes lose their state. Use data-ignore-morph for an unchanged subtree and data-jqs-preserve for a retained live application root. Await $.star.whenEnhanced() before reading enhanced DOM.

The repository's Component Lab includes real JSON, HTML, multipart, and official-SDK stream endpoints when run through the local proof server.
