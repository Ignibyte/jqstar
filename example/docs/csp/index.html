CSP expressions

jqstar-csp-expression/1 is the shipped finite language contract for the jquery-star/csp expression engine. The package provides an explicit installer, ESM and CommonJS formats, matched declarations, and a strict-policy browser proof.

CSP compatibility means no dynamic code construction in the CSP engine or its package entry graph. It requires trusted markup and trusted installed extensions. It is not a sandbox and does not make attacker-authored expressions safe.

The page policy—not jQStar—governs inline scripts, styles, network endpoints, third-party jQuery plugins, and application code. Applications still own authorization, CSRF protection, output encoding, HTML sanitization, Trusted Types, and server validation.

Two engine profiles

Profile Language Status
Trusted JavaScript Current JavaScript expressions and statements, including real jQuery. Shipped; requires unsafe-eval.
CSP Closed finite grammar with capability-specific reads, writes, and calls. Shipped as an explicit optional entry.

CSP selection is explicit. It does not weaken or silently replace the trusted engine, and the compatibility root never auto-selects it.

Install the CSP runtime

Import the CSP entry directly and call installStarCSP() before installing plugins or booting applications. Do not import the compatibility root on the same jQuery instance because that root retains the trusted JavaScript engine.

app.ts 
import $ from "jquery";
import { installStarCSP } from "jquery-star/csp";
import { datastarPlugin } from "jquery-star/datastar";
import { uiPlugin } from "jquery-star/ui";

const installed = installStarCSP($);
installed.star.use([datastarPlugin, uiPlugin]);
installed.star.boot(document);

Repeated CSP installation returns the same owner. A live incompatible engine is rejected. Advanced hosts can pass createCSPExpressionEngine() through the explicit jquery-star/core engine seam. Separate jQuery/kernel owners can select different engines.

Server policy

Importing the entry does not add response headers. The installed-package proof starts from this policy and serves scripts and styles as external same-origin assets:

Content-Security-Policy
default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self'; font-src 'self'; base-uri 'none'; object-src 'none'; frame-ancestors 'none'; form-action 'self'

Adapt allowed origins to the application. If a report names unsafe-eval, verify that the page did not import the package root and that another script or jQuery plugin did not construct code.

Supported expression shape

The finite profile keeps the framework meanings stable: $ is real jQuery and a name such as $count is a reactive signal. It supports bounded literals, arrays, plain objects, reviewed operators, conditionals, state reads and writes, event and argument data, named actions, committed helpers, and a closed jQuery method table.

finite-profile.html 
<section data-signals="{ count: 0, saved: false }">
  <button data-on:click="$count += 1; return action('save', $count)">
    Save
  </button>
  <output data-text="$saved ? 'Saved' : $count"></output>
</section>

Functions, classes, declarations, loops, exceptions, modules, arbitrary calls, ambient globals, callbacks, and automatic semicolon insertion are not part of the language. return and await are available only in the statement entry point.

Capability boundary

Origin Allowed authority
$name, state, signals Read safe paths; write only approved state paths.
computed, args, evt Read reviewed data; event calls are limited to default and propagation control.
el, root, $el, $root Read same-realm values and use the reviewed jQuery table within the application root.
action('name'), @name Invoke a source-literal registered action with bounded arguments.
Committed helper path Invoke only that exact installed helper leaf.

The evaluator rejects constructor, prototype, __proto__, call, apply, bind, reflective lookup, accessors, inherited properties, arbitrary thenables, and any function obtained as data. Escaped, computed, concatenated, or result-derived spellings do not bypass the check.

jQuery and trusted HTML

Selectors, HTML passed to html(), class names, attribute/property names, and CSS property names must be source string literals. Selectors are scoped to root and collections are bounded. Callback-taking methods, event registration, queue control, jQuery network helpers, script evaluation, and arbitrary plugin methods are excluded.

A CSP expression may deliberately select elements, mutate DOM and state, insert application-trusted literal HTML, invoke an authorized action or helper, and initiate a request through that capability. HTML responses that can add expression-bearing attributes are therefore trusted markup. JSON signal patches, form values, events, and return data stay data and are never reparsed as expressions.

Deterministic limits

Resource Maximum
Source length 2,048 UTF-16 code units
Tokens / AST nodes / evaluation steps 512 / 256 / 128
Nesting / path segments / call arguments 16 / 8 / 8
Literal entries / collection size 64 / 128
Approved asynchronous chain 8

Errors carry a stable CSP_* code, compile or evaluate phase, grammar version, authored attribute and source, zero-based UTF-16 offsets, and 1-based line and column spans. Diagnostics do not serialize state, DOM, credentials, response values, arguments, or rejection causes.

Migration from trusted JavaScript

Most current public expressions are exact finite-profile matches. Ambient JavaScript and arbitrary jQuery extensions move behind registered, application-owned actions or helpers.

Trusted expression CSP migration
console.log($count) Register and call an application diagnostic action or helper.
$(el).datepicker() Register an integration action that owns the plugin call.
Promise.resolve($count) Return an approved asynchronous result from an action or helper and await it.
this Use the explicit el binding.

Version and verification

The versioned contract combines the grammar, capabilities, limits, diagnostics, accepted and denied source, adversarial payloads, executable-context recipes, shared-engine mapping, and public-example inventory. Raising a limit or changing accepted source requires a new grammar version and review. The repository command npm run test:csp-contract validates the frozen inputs and prints their combined SHA-256 digest.

Package quality runs the exact ESM and CommonJS artifacts plus this public interaction shape in Chromium, Firefox, and WebKit. Continue with the Core API, plugin boundary, or testing harness.
