Turbo and htmx interoperability

jQStar has tested bridges for wrapping external DOM renders without taking over the host library. The jquery-star/turbo and jquery-star/htmx previews both ship now.

One ownership seam: the host sends requests and mutates the DOM. A bridge uses createRenderAdapter() only to release outgoing jQStar roots, preserve exact approved identities, enhance incoming roots, and await the barrier.

Tested version boundaries

Host Approved evidence range Tested packages
Turbo >=8.0.21 <8.1.0 8.0.21 and 8.0.23
htmx >=2.0.0 <2.1.0 2.0.0 and 2.0.10

Missing, prerelease, unknown, and out-of-range versions fail before a bridge installs listeners. The htmx bridge also requires the explicit version to match htmx.version. jQStar does not auto-detect or load either host.

Install the Turbo bridge

Explicit Turbo capability and version
import * as Turbo from "@hotwired/turbo";
import $ from "jquery";
import { installStarCore } from "jquery-star/core";
import { createTurboBridge } from "jquery-star/turbo";

const { star } = installStarCore($);
const bridge = star.use(
  createTurboBridge({ $, Turbo, version: "8.0.23" }),
);

await bridge.whenIdle();

Use the exact installed Turbo package version. Importing the bridge is inert. Installing it registers document-scoped public event listeners but never calls Turbo start or navigation APIs. bridge.dispose() removes those listeners without disposing Turbo or the jQStar kernel.

Install the htmx bridge

Explicit htmx capability and version
import htmx from "htmx.org";
import $ from "jquery";
import { installStarCore } from "jquery-star/core";
import { createHtmxBridge } from "jquery-star/htmx";

const { star } = installStarCore($);
const bridge = star.use(
  createHtmxBridge({ $, htmx, version: "2.0.10" }),
);

await bridge.whenIdle();

Use the exact installed htmx package version. Importing the jQStar bridge is inert. Installing it registers document-scoped public lifecycle listeners but never calls htmx.ajax(), htmx.process(), htmx.swap(), or htmx.trigger(). whenIdle() waits for bridge-owned render and jQStar enhancement work, not arbitrary htmx requests or network idleness.

Lifecycle

External render state machine
prepared
  -> removing
  -> externally-mutated
  -> enhancing
  -> committed

Terminal alternatives: canceled or failed

Cancellable intent creates no render transaction. A real mutation starts at Turbo's pausable document or Frame render callback, or at the approved htmx swap and cleanup seam. Every opened transaction commits or fails once.

Host-specific differences

Flow Observed contract
Turbo document or Frame Wrap detail.render, then commit before host completion.
Turbo form submit-end and before-visit can reverse across browsers. Both precede render.
htmx replacement Deduplicate nested cleanup, commit after the host swap, and finish at settle.
htmx delete Cleanup and afterRequest occur without afterSwap or afterSettle.
htmx no-swap afterSwap may fire even when no target mutation occurs.

Preservation and focus

data-jqs-preserve remains the core marker. The Turbo bridge also passes an exact old data-turbo-permanent element, and the htmx bridge does the same for hx-preserve. In each case, the old element must be connected, inside the outgoing boundary, uniquely identified, matched once in the incoming content, and retained after mutation. Duplicate, missing, disconnected, moved, or cross-document candidates are cleaned and diagnosed.

The tested hosts retain DOM and control-value identity for valid permanent elements but can move focus to the activated control. Focus remains host-owned. A bridge must not add a focus correction unless a later contract explicitly approves and tests one.

Proof and limits

Actual boundary packages run in Chromium, Firefox, and WebKit against native links and forms, document and region changes, history, cache, preservation, cancellation, no-content responses, and failures. Semantic traces omit URLs, form values, headers, bodies, HTML, DOM objects, signal values, and raw errors.

Turbo Streams, morph refresh, custom Turbo renderers, custom htmx swap extensions, shadow or cross-document targets, and script execution guarantees are outside this contract. Read the complete repository contract for every stable mapping ID and update rule.

htmx troubleshooting

  • An installation error usually means the explicit version differs from htmx.version, falls outside >=2.0.0 <2.1.0, or the capability is incomplete.
  • A prevented swap can indicate a disconnected target, unsupported swap style, duplicate main swap, or overlapping active boundary. Pass onError and inspect bridge.observations() for redacted evidence.
  • A recreated preserved root needs the same unique, non-empty id on the old and incoming hx-preserve or data-jqs-preserve element.
  • A pending whenIdle() is waiting for a mapped htmx terminal event or jQStar enhancement. Call dispose() during shutdown.
