Plugins

A jQStar plugin is a synchronous, transactional extension. It declares a versioned manifest and stages public capabilities; jQStar publishes them together only after the complete plugin graph validates and installs.

Structural boundary: install plugins before the first application starts. External plugins own one dot-qualified namespace and import documented package entries, never source files or kernel internals.

Register public capabilities

plugin.ts 
import { STAR_PLUGIN_API_VERSION, type StarPlugin } from "jquery-star/core";

export const auditPlugin: StarPlugin = {
  name: "acme.audit",
  version: "1.0.0",
  apiVersion: `^${STAR_PLUGIN_API_VERSION}`,
  install(registrar) {
    registrar.action("acme.audit.mark", ({ state }) => {
      state.audited = true;
    });
    registrar.helper("acme.audit.label", "Audited");
    registrar.application(({ root }) => {
      root.setAttribute("data-audited", "true");
      return () => root.removeAttribute("data-audited");
    });
    registrar.cleanup(() => releasePluginResources());
    return Object.freeze({ ready: true });
  },
};

The same registrar can stage namespaced directives, request middleware, protocol profiles, operation observers, activation work, and document-host resources. Register cleanup as soon as a side effect exists. Failed installation and normal disposal run represented callbacks in reverse order and attempt every callback after an individual failure.

Run conformance against the packed package

Publish or pack the plugin as its own package, install it beside the packed jQStar tarball, and construct the harness only from jquery-star/testing. This catches private source imports, undeclared dependencies, workspace aliases, incompatible declarations, and differences between repository and installed-package behavior.

plugin-conformance.ts 
import { runPluginConformance } from "jquery-star/testing";
import {
  auditPlugin,
  cleanupFailingPlugin,
  installFailingPlugin,
} from "acme-audit-plugin";

const report = await runPluginConformance({
  createHarness,
  plugin: auditPlugin,
  failingPlugin: installFailingPlugin,
  cleanupFailingPlugin,
  async exercise(harness) {
    const root = harness.document.createElement("section");
    harness.document.body.append(root);
    const app = harness.mountBehavior(root, { state: { audited: false } });
    await app.instance.run("acme.audit.mark");
    if (!app.state.audited) throw new Error("plugin action did not run");
  },
});

The shared cases prove repeated installation returns one facade, public use succeeds, failed installation rolls back, disposal runs once, later cleanup still runs after a failure, and the frozen public disposal report names the failed plugin owner. The functions contain no runner imports or suite registration.

External navigation

Navigation and page-transition plugins replace DOM through createRenderAdapter() from jquery-star/core. The adapter destroys outgoing application roots deepest-first while they remain connected, retains explicit data-jqs-preserve identities and control state, validates the committed roots, restores focus, boots incoming data-jqs roots, and waits for enhancement. The caller performs the actual DOM mutation.

Wrap each navigation in one public operation observation. Keep the same operation ID from started through exactly one completed or failed terminal record, and do not expose markup, signal values, or live nodes in observation metadata.

What conformance does not prove

Conformance checks jQStar's public registrar, application, request, rendering, observation, rollback, and disposal contracts. It does not certify the plugin's product logic, security, accessibility, arbitrary timers, network services, or memory use. Add focused tests for those claims and use the runner adapter described in the testing guide.
