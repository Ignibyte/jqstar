Core API

jQStar is HTML-driven, but its installed jQuery surface exposes explicit application, action, request, lifecycle, and UI methods for code that needs programmatic control.

The root surface preserves the 0.1 compatibility contract. The core, ui, datastar, csp, testing, datastar/testing, turbo, and htmx package subpaths are stable in 1.0.

Applications

API Purpose
$(root).star() Start an attribute-driven application on the matched root.
$(root).star(definition) Start an application from a typed behavior definition.
$.star.boot(root?) Boot the document element or the supplied root.
$(root).star("instance") Read the installed application instance.
$(root).star("state") Read its reactive state object.
$(root).star("refresh") Refresh computed bindings and directives.
$(root).star("destroy") Destroy that application and its owned effects.

Named actions

Use named actions for behavior that is too long for an attribute. The callback receives real jQuery, reactive state, computed values, root and initiating elements, the event, authored arguments, and the application instance.

main.ts 
$.star.action("removeItem", ({ $element, state }) => {
  $element?.closest("li").fadeOut(180, function () {
    $(this).remove();
  });
  state.itemCount = Math.max(0, Number(state.itemCount) - 1);
});
items.html 
<button data-on:click="@removeItem">Remove</button>

Backend actions

$.star.get, post, put, patch, and delete return ordinary named-action functions. The same methods are available declaratively as @get, @post, and their peers.

main.ts 
const app = $("#items").star("instance");

await app?.run($.star.post("/items", {
  payload: { title: "Proof" },
  pending: "saving",
  error: "saveError",
  retry: "never",
}));

UI methods

$.star.ui groups component-specific methods such as dialog.open, tabs.activate, menu.close, and toast.show. Named @ui.* actions call the same behavior from HTML. $.star.ui.enhance(root) scans newly authored component markup when an explicit application integration needs it; normal jQStar and Datastar patches enhance automatically.

main.ts 
$.star.ui.dialog.open("#account-dialog", {
  initialFocus: "#account-dialog-cancel",
});

$.star.ui.tabs.activate("#settings-tabs", "security");

$.star.ui.toast.show({
  title: "Saved",
  description: "Your changes are live.",
  variant: "success",
});

Scheduling and version

$.star.nextUpdate() resolves after the next reactive update flush. $.star.whenEnhanced() waits for pending render transactions, observer delivery, directive and UI enhancement, and the resulting reactive work. Use it before reading DOM inserted by an HTML or Datastar patch. $.star.version reports the installed runtime version, and $.star.clearExpressionCache() clears the current expression engine's cache.

Terminal disposal

$.star.dispose() permanently closes one document installation, attempts every owned cleanup, releases its document and expression-engine claims, and returns a frozen JSON-safe report. A cleanup failure throws StarDisposalError after the complete sweep and retains that report. Repeated disposal returns the same report or throws the same error object.

Continue with the CSP expression contract, the testing harness, or the plugin contract and conformance guide.
