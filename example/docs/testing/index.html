Testing

The stable jquery-star/testing entry supplies a runner-neutral harness for public jQStar behavior. You choose the DOM implementation and jQuery instance; the harness owns only the installation, applications, response fixtures, and finite work created through it.

Explicit ownership: importing the testing entry does not create a DOM, install jQStar, replace fetch, or register a test suite. The generic entry does not import a DOM package, test runner, or Datastar.

Create an isolated harness

Supply one same-realm Window, its Document, and the jQuery instance that selects elements from that realm. Use withStarDOMRealm() only when the DOM or jQuery package needs ambient browser globals; the lease is process-wide, rejects overlap, and restores the documented global property descriptors after success or failure.

application.test.ts 
import { JSDOM } from "jsdom";
import {
  createResponseController,
  createStarHarness,
  withStarDOMRealm,
  type StarDOMWindow,
} from "jquery-star/testing";

const dom = new JSDOM('<section id="app" data-signals="{ ready: false }"></section>');
const window = dom.window as unknown as StarDOMWindow;

await withStarDOMRealm({ window }, async () => {
  const { default: $ } = await import("jquery");
  const responses = createResponseController({ window });
  responses.json({ url: "https://example.test/state" }, { ready: true });

  const harness = createStarHarness({ window, jQuery: $, responses });
  try {
    const root = window.document.querySelector("#app");
    if (!root) throw new Error("application root is missing");
    const app = harness.mountDeclarative(root);
    await app.instance.run(harness.installed.star.get("https://example.test/state"));
    await harness.flush();
    if (harness.state(app).ready !== true) throw new Error("state did not settle");
  } finally {
    harness.dispose();
  }
});

What flush waits for

flush() drains jQStar reactive and enhancement work, queued response delivery, and finite promises registered with harness.task(), including work those tasks register transitively. It has round and time bounds. It does not wait for arbitrary timers, animation loops, third-party promises, or real-network idleness.

A bound breach throws StarFlushError. Its JSON-safe diagnostic contains elapsed time, rounds, and only the outstanding operation, request, or task IDs and stable owners. It never includes signal values, request bodies, callbacks, elements, or other live objects.

Queue exact responses

createResponseController() is a strict FIFO boundary. It records method, URL, normalized headers, body, and abort signal; rejects unexpected or mismatched requests; and reports unused expectations during disposal. Use json(), html(), empty(), httpError(), networkError(), delay(), retry(), and abort(). There is no network passthrough.

jquery-star/datastar/testing adds success, ordered multi-event, chunked, retry, malformed, failure, and abort fixtures. Valid event bytes come from the official Datastar SDK. Keeping them in a separate entry prevents Datastar from entering generic test and core graphs.

Use any test runner

runCoreConformance(factory) runs the same named public cases under Vitest, QUnit, plain Node, or a browser adapter. It returns an immutable report or throws StarConformanceError; the caller maps that result to its runner's assertions. See Plugin conformance for the external-package path.

Teardown limits

Harness disposal is idempotent and restores every fetch property it replaced. It consumes the public frozen disposal report, whose attempted, released, failed, and remaining entries identify jQStar-owned categories and stable owners. This is not a heap-leak detector and makes no claim about timers, listeners, or promises created outside jQStar capabilities.
