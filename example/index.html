TLDR · why jQStar

Bring jQuery back. Keep the server in charge.

jQuery got a bad name from sprawling event handlers and hidden DOM state. jQStar brings it back with explicit signals, owned behavior, and cleanup. For server-rendered apps, React can add more machinery than the interaction needs. Write HTML. Enhance what moves.

Server side is king: keep data, permissions, and validation on the backend. Our bet for the AI future is strong servers with focused browser work. Give people and coding agents the same inspectable HTML, contracts, and working examples. Measure performance against your own workload.

Features you can use today

  • Real jQuery for selectors, plugins, and existing application code.
  • Reactive signals and named actions declared through HTML attributes.
  • 102 source-owned component recipes and seven composed application blocks.
  • Native controls, keyboard behavior, focus management, and form submission.
  • HTML and JSON updates, plus Datastar streams from the official SDK.
  • Enhancement and disposal when the server replaces a region.
  • Script-tag setup or modular packages, with incremental adoption.

Built for people and coding agents

  • Readable HTML that the backend and an agent can both inspect.
  • Documented component roots, parts, state, and ownership.
  • Copy-in recipes that your application owns and can edit.
  • A complete live Component Lab on this page.
  • One reviewed reference through llms.txt and llms-full.txt.
  • Optional read-only WebMCP tools for supported browsers.
  • Optional stores, persistence, and inspection for larger applications.

$ is real jQuery. $name is a reactive signal. Named actions move longer behavior back into JavaScript.

No virtual DOM or duplicated client routes. jQStar is not an official successor to jQuery UI or jQuery Mobile.
